# Agent Specialist Context — Current Stage

## Objective
Build a controlled research agent that combines RAG evidence, Gemini generation and allow-listed tools.

## Current architecture
`Backend -> ResearchAgent -> RAG context + Gemini Interactions API -> controlled tools -> final answer`

## LLM interface
The application uses `google-genai` and Gemini Interactions API.

Tool execution is application-controlled:
1. model returns `function_call`
2. Python allow-list executes the function
3. application sends `function_result`
4. interaction continues through `previous_interaction_id`

Tool rounds are bounded by `MAX_TOOL_ROUNDS`.

## Current tools
- calculator
- get_current_date

The calculator must never use `eval()` or execute arbitrary Python.

## RAG contract
Treat RAG as a black box:
`retrieve(query, top_k) -> structured sources/chunks`

## Output
Return:
- query
- answer
- sources
- tool_calls

## Token/cost rules
- Prefer local embeddings.
- Keep retrieval context bounded by `RAG_MAX_CONTEXT_CHARS`.
- Do not resend an entire interaction history when server-side interaction state can be used.
- Do not introduce autonomous multi-agent loops without a concrete requirement.

## Do not
- implement FastAPI endpoints
- change RAG internals without updating its contract
- execute model-requested code outside the allow-list

# Current Technology Guidance

This file records the engineering decisions for the current repository state.

## Gemini
Use the official `google-genai` SDK.

The application model is configurable with `GEMINI_MODEL`; current default:
`gemini-3.8-flash`.

Gemini 3.8 Flash is currently GA and supports function calling and structured outputs. The Gemini Developer API currently lists a Free Tier for Gemini 3.8 Flash. Do not hard-code the model into business logic.

Use the Gemini Interactions API for agent workflows. For tool loops, prefer server-side interaction chaining with `previous_interaction_id` so application code does not repeatedly resend the full history.

## Embeddings
The default embedding path is local and free:

`FastEmbed -> ONNX -> sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 -> 384 dimensions`

FastEmbed is intentionally used instead of Sentence Transformers/PyTorch because it is lightweight and CPU-oriented.

Gemini Embedding 2 remains an optional replaceable provider. It must not be required for normal low-cost development.

When changing embedding provider/model/dimension, treat the vector collection as incompatible until it is deliberately reindexed.

## RAG
Keep these responsibilities separate:

`document -> extraction -> chunking -> embedding -> vector storage -> retrieval -> context assembly`

Retrieval must return source metadata and scores.

Indexing must be separate from querying.

The RAG contract is `contracts/rag_contract.json`.

## Tools
Use explicit Gemini function declarations.

The model never receives permission to execute arbitrary Python. The application maps requested tool names to an allow-list and executes only those functions.

Keep tools deterministic where possible.

## Backend
Use FastAPI + Pydantic + SQLAlchemy.

SQLite is acceptable for this local, low-cost project. Do not introduce PostgreSQL until actual concurrent/scale requirements justify it.

Use versioned API paths under `/api/v1`.

## Architecture
Prefer a modular monolith.

Do not introduce microservices, MCP, Kubernetes, or other infrastructure merely for fashion. Add them only when a concrete requirement is demonstrated.

## Testing
Test:
- unit behavior
- component contracts
- API validation
- failure cases
- retrieval relevance
- agent tool behavior

Model/network calls should be replaceable by deterministic fakes in CI.

## Deployment
Docker Compose runs backend and frontend separately.

Runtime state stays outside Git:
- Qdrant data
- SQLite DB
- FastEmbed model cache
- uploaded runtime documents when appropriate
- secrets

## General rule
Choose the simplest current technology that satisfies the requirement, while preserving replaceability, testability, security, observability, and low cost.
